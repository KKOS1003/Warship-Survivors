# 《战舰，最后的防线》V26 增量更新说明

## 增量包，不包含模型

这是**覆盖到 V25 游戏文件夹**中的补丁，不是独立完整游戏。**不包含任何 `.glb`、`.gltf`、`.zip` 模型、贴图或玩家/敌军 JSON**；沿用你现有的 `assets/`、`ships/` 和已安装的 `vendor/`。

1. 将 V25 的游戏文件夹备份。
2. 解压 V26 增量包，将其中 `index.html`、`index-online.html`、`index-local.html`、`serve.py` 和 `assets/underwater_visual_fx.js` 按原有目录覆盖/新增到 V25 的游戏目录。
3. **不要删除或替换旧目录中的其他文件**，尤其是 `assets/*.glb`、`assets/*.zip`、`ships/`、`vendor/` 和 `install_dependencies.py`。
4. 在游戏目录启动 `python serve.py --host 0.0.0.0 --port 8000`；如果服务器尚未安装依赖，首次可运行 `python serve.py --install --host 0.0.0.0 --port 8000`。
5. 客户端打开 `http://服务器地址:8000/`。请勿直接以 `file://` 打开 HTML。

## 水下相机（实验性视觉层）

- 在战斗中切换到**自由相机**（B），按 `-` 键下降到海平面以下（最深约 -85 米），按 `=` 上升。自由相机仍可 WASD 移动。
- 入水后叠加蓝绿色光吸收、纵深雾、浅水太阳光束、水纹与悬浮微粒；Three.js 战舰层切换裁剪规则，水下也能看到吃水线以下的船体部分。
- 设置 → 海况与天气 → **水下相机视觉** 可关闭效果或调节强度。水下雨丝会暂时隐藏。
- 这是**独立水下视觉模拟**，**不是** Open Water 的原生水下折射、体积光或波面深度测试。不同海况下实际波峰高度会变化，当前入水阈值以近似平均海平面 `y=0` 为准，极端风浪可能产生不精确的过渡；没有实现水下声学与海底环境。
- 手机和低端设备减少粒子数、绘制分辨率。

## 修复 JavaScript ES Module MIME 错误

旧版在线加载失败后尝试通过 `raw.githubusercontent.com` 加载 Open Water 的 `src/main.js`；该网站经常以 `Content-Type: text/plain` 返回源码，**ES Modules 会被浏览器拒绝执行**。V26 已删除这一无效回退。

- `serve.py` 的 `ModuleSafeHandler` 明确将 `.js` / `.mjs` 以 `text/javascript`、`.wasm` 以 `application/wasm` 提供。此修复作用于**游戏服务器**，客户端无需安装任何依赖。
- `index.html` 启动器会检查脚本响应的**实际 MIME 类型**，并优先使用服务器上的 `vendor` 模块，只有未安装时才尝试可用的在线源。
- `index-online.html` 不再自动向 GitHub Raw 回退；模块网络失败时会提示使用服务器本地依赖。
- 单纯将 `.js` 文件改名不能解决 MIME 问题；若使用 Nginx、Apache、对象存储或其他静态服务器，须在该服务器配置对应的 MIME 映射（`text/javascript`）。

**验证 MIME：**
```bash
curl -I http://localhost:8000/assets/underwater_visual_fx.js
curl -I http://localhost:8000/vendor/open-water/src/main.js
```
正常应包含 `Content-Type: text/javascript`。第二条若返回 `404`，说明 `vendor` 尚未在服务器安装，需在服务器端运行 `python install_dependencies.py`。

如使用 Nginx，确保配置包含 `js`、`mjs` 对应 `text/javascript` MIME（通常在 `mime.types` 中）；更新后重新加载 Nginx 并清理浏览器缓存。
